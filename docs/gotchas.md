# Gotchas

**Limit: 80 lines**, one line each: **delete the line when it stops being true.**
`docs/STATUS.md` links here; the code wins if the two ever disagree.

## The cart and the licence

- **Never commit `assets/upstream/`** — the cart is "No License"; it was committed by
  accident early on and the repo had to be replaced. Art and audio come from
  `__gfx__`/`__map__`/`__sfx__`/`__music__` through `tools/p8_import.py` into
  `assets/*.bin`: derived data, like `src/consts.rs`.

## Fixed point and trig

- Everything is 16.16 (`Fix = i32`) and literals quantise too (`0.96` → 62914):
  compare against the quantised constant, never the decimal.
- `sin`/`atan2` are **y-inverted** and run **anticlockwise**: `sin(0.25) = -1`, and a
  quarter turn sends `(72,64)` to `(64,56)` while `(64,64)` never moves.
- `px2rpx` is **not bit-exact** (`f64` quantised, worst 324/65536 px); `mid(lo,v,hi)`
  needs sorted bounds, though the cart tolerates `lo > hi`.

## Torque and aiming

- Torque `0.05` needs **110** frames to reach 0; aiming is asymmetric (left → x=50, right → x=77).
- `update_bubble` mutates its own copy: Rust must write the **whole struct** back or a
  bounce flips a `dx` nobody stores (five "bounces" in five frames).
- A shot straight down the centre gives **zero** torque, and the mass aims its own
  shots through the centre.

## Grid, board and rules

- Cell values are `u16` (`colour + 10*pop + 300*explode`, up to ~609): delete only at
  `v > 600`, settled is `v < 10`, and `keys()` skips `v >= 10` plus the centre 262.
- `get_dest_cell` can be `nil` (the cart would index the board with it); the port gives
  the shot up instead.
- `neighbors()` wraps the last column into the next row and never bounds `y` upward —
  both are the cart's own quirks and both change which gumballs fall.
- Layout: `b2px(i) = (x*8-16 (+4 odd rows), y*7-20)`, `B_R = 4`, centre 262 at (64,64).
- `src/consts.rs` is generated by `tools/extract_level.py` (`--check` guards it).
- `check_over` **ceils** the rotated position, so cell centres live in `[8,121]`: 122
  ends the game (the M5 issue's "124" is wrong).
- `f_bubs = bubs` on game over joins the loaded bubble to the cascade; `drop_bubs`
  divides by `flr(rnd(#f_bubs/20))`, which is 0 under 20 bubbles — guard it.

## Drawing

- `pal()`/`palt()` apply **when the pixel is drawn**, not when the frame is converted
  (a later reset must not repaint); colour 0 is transparent by default, and
  `cls`/`rectfill`/`pset` ignore transparency while `spr`/`sspr` honour it.
- `map()` is 128×16 tiles, i.e. the **whole 128×128 screen**, so background assertions
  must sample map pixels rather than the corner.
- **PICO-8's font is not in the cart** (it is in PICO-8's ROM at `0x5600`); `__gfx__`
  is sprites only. The port bundles Tom Thumb at PICO-8's 4 px advance, 6 px line.
- Golden frames are byte-compared PNGs in `tests/golden/`; re-record with
  `UPDATE_GOLDENS=1 cargo test --test screens` after an intended visual change.

## Audio

- `.p8` `__sfx__` is **not** the 68-byte RAM layout: a line is 84 bytes of packed
  five-nibble notes, and music channel bytes are **6-bit** sfx ids (`0x41..0x44` → 1..4,
  so mask `0x3f`). A note is `speed * 183/22050` s; pitch 0 is C0 = 65.4 Hz.
- **`macroquad`'s `audio` feature is opt-in** (`default = []`): without it `play_sound`
  links a dummy backend and only prints a warning. `tests/build_config.rs` pins it.
- PICO-8's waveforms are engine code, not cart data, so ours are shapes; the 2 ms
  anti-click ramp is ours too. `sfx(18)` is **two** notes = 66 ms, not the M7 issue's
  "0.1–0.4 s". Music is baked lazily and looped.

## Save file

- The cart reads the hiscore then `dset(0,0)`, so it survives only if you beat it again.
  **Not ported**; `save.dat` sits beside the executable and corrupt files are ignored.

## Tooling and the repo

- Rust and the system libraries are in the image: **do not install anything.** If
  `cargo fetch` fails, stop and ask.
- CI (`.github/workflows/build.yml`) tests and builds Windows and Linux artifacts.
- The `gh` token is **fine-grained**: it pushes and opens PRs but cannot create or
  delete repositories or change settings (ask the human). Issues and PRs share one
  number sequence, so the milestones are #1–#8.
